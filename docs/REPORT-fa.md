# گزارش تغییرات Application API نسخه 2.2.4

## قرارداد یکپارچه action

ساختار `action` برای تمام محل‌های مجاز یکسان شد. این ساختار فقط در دو محل ساخته می‌شود:

1. برای هر آیتم بخش تصویر؛
2. برای `view_all` بخش‌های محصولات، دسته‌بندی‌ها و برندها.

برای تک‌تک محصولات، دسته‌بندی‌ها یا برندهای داخل `data` هیچ `action` اضافه‌ای ساخته نمی‌شود.

```json
{
  "title": "لپ‌تاپ",
  "type": "category",
  "destination_id": 55,
  "on_sale": false,
  "url": null,
  "orderby": "date",
  "order": "desc"
}
```

## عنوان action

پارامتر `title` قابل ویرایش جداگانه نیست و همیشه از عنوان صاحب action گرفته می‌شود:

- در بخش تصویر، دقیقاً برابر `title` همان تصویر است؛
- در `view_all`، دقیقاً برابر عنوان «مشاهده همه» همان بخش است.

به این ترتیب عنوان قابل نمایش صفحه مقصد با عنوان آیتم انتخاب‌شده هماهنگ می‌ماند.

## نوع مقصد و مقصد

نوع‌های قابل انتخاب عبارت‌اند از:

- محصول: `product`
- دسته‌بندی: `category`
- برند: `brand`
- لینک: `url`
- بدون عملیات: `null`

برای محصول، دسته‌بندی و برند، فیلد تنظیمات با عنوان «شناسه مقصد» نمایش داده می‌شود و خروجی `destination_id` عددی است. برای لینک، عنوان فیلد به «لینک مقصد» تغییر می‌کند، `destination_id` برابر `null` می‌شود و آدرس در `url` قرار می‌گیرد.

## وضعیت تخفیف

گزینه «فقط محصولات تخفیف‌دار نمایش داده شوند» فقط هنگام انتخاب مقصد دسته‌بندی یا برند نمایش داده می‌شود:

- تیک‌خورده: `on_sale: true`
- بدون تیک: `on_sale: false`
- مقصد محصول، لینک یا بدون عملیات: `on_sale: null`

## مرتب‌سازی

برای هر action دو فیلد انتخابی اضافه شد:

- `orderby`: `date`، `price`، `popularity`، `rating` یا `cout_sales`
- `order`: `desc` یا `asc`

مقادیر پیش‌فرض `date` و `desc` هستند. مقدار `cout_sales` در API فهرست محصولات نیز پشتیبانی می‌شود و مرتب‌سازی را بر اساس تعداد فروش ووکامرس انجام می‌دهد.

## view_all برای دسته‌بندی‌ها و برندها

بخش‌های `category` و `brand` نیز اکنون مانند بخش محصولات دارای `view_all` قابل تنظیم هستند. عنوان، نوع مقصد، شناسه یا لینک مقصد، وضعیت تخفیف و نحوه مرتب‌سازی از پنل تنظیمات قابل تعیین است.

## سازگاری با نسخه‌های قبلی

ساختارهای قدیمی `destination`، `id` و `url` هنگام خواندن تنظیمات به قرارداد جدید مهاجرت می‌شوند. عنوان action در زمان ساخت پاسخ دوباره از عنوان واقعی آیتم گرفته می‌شود تا داده قدیمی یا ناسازگار وارد JSON نشود.
