# گزارش تغییرات Application API نسخه 2.2.2

## عمومی‌سازی متن‌ها

تمام اشاره‌های فارسی و انگلیسی به یک فناوری یا فریم‌ورک مشخص از صفحه تنظیمات، توضیحات کد و مستندات حذف شد. متن راهنمای چیدمان اکنون به‌شکل عمومی درباره «اپلیکیشن» نوشته شده است.

عنوان بالای پنل اکنون فقط این متن را دارد:

`صفحه‌ساز بصری API اپلیکیشن`

دکمه «مشاهده API خانه» نیز حذف شده است.

## endpoint قابل تنظیم

در تب هر API پیاده‌سازی‌شده، نام endpoint و آدرس کامل آن نمایش داده می‌شود:

- تب خانه: endpoint پیش‌فرض `home`
- تب فروشگاه: endpoint پیش‌فرض `products`
- تب محصول: endpoint پیش‌فرض `products/{id}`

برای نمونه، تغییر endpoint خانه به `main-page` آدرس را به مسیر زیر تغییر می‌دهد:

`/wp-json/app-api/v1/main-page`

نام endpoint پاک‌سازی می‌شود و فقط حروف انگلیسی، عدد، خط تیره و زیرخط را می‌پذیرد. endpoint خانه و فهرست محصولات نمی‌توانند یکسان باشند.

## سطر و ستون

`rows` و `columns` برای همه بخش‌ها همیشه در JSON وجود دارند و عدد صحیح حداقل `1` هستند. اگر فیلد خالی، صفر یا نامعتبر باشد، مقدار `1` ذخیره و برگردانده می‌شود.

## نوع ثابت بخش‌ها

نوع بخش هنگام ساخت انتخاب می‌شود و بعد از ایجاد قابل تغییر نیست. این محدودیت هم در رابط مدیریت و هم هنگام پاک‌سازی داده‌های ذخیره‌شده اعمال شده است.

نوع‌های اصلی:

- محصولات: `products`
- دسته‌بندی: `category`
- بنر: `banner`
- برند: `brand`

منوی دسترسی سریع موجود نیز نوع ثابت `menu` دارد. تنظیمات قدیمی با نوع‌های جمع `categories` و `brands` به‌صورت خودکار به `category` و `brand` تبدیل می‌شوند.

## خروجی بنر

از آیتم‌های بنر این پارامترها حذف شدند:

- `id`
- `action`
- `parent`

هر آیتم بنر فقط عنوان، زیرعنوان و لینک تصویر را برمی‌گرداند. فیلدهای ID و مقصد نیز از ویرایشگر آیتم بنر در پنل حذف شده‌اند. تنظیمات مقصد آیتم‌های منو همچنان حفظ شده است.

## خروجی دسته‌بندی

پارامتر `action` از آیتم‌های بخش دسته‌بندی حذف شد و شناسه عددی `id` برای بازکردن صفحه دسته‌بندی باقی ماند.

## نام ثابت فیلترها

در `view_all.action` بخش محصولات، نام پارامترها همیشه مفرد باقی می‌ماند:

- `category`
- `brand`

این نام‌ها با افزایش تعداد ID به `categories` یا `brands` تبدیل نمی‌شوند.
