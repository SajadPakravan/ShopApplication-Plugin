# گزارش تغییرات Application API 2.5.2

## اصلاح مقصد دکمه «مشاهده همه»

- `destination_id` از **Action دکمه‌های View All** حذف شد.
- دو پارامتر ثابت جایگزین شدند: `category_id` و `brand_id`.
- هر دو پارامتر همیشه آرایه هستند تا قرارداد JSON برای یک یا چند شناسه تغییر نکند.
- در بخش محصولات، اگر فیلتر دسته‌بندی وجود داشته باشد `type = category` می‌شود؛ اگر دسته‌بندی خالی و برند موجود باشد `type = brand` می‌شود؛ فقط در صورت نبود هر دو فیلتر `type = all` است.
- اگر هم دسته‌بندی و هم برند روی یک لیست محصول اعمال شده باشند، `type = category` است و هر دو آرایه `category_id` و `brand_id` حفظ می‌شوند تا اپلیکیشن بتواند فیلتر ترکیبی را بازسازی کند.
- در بخش دسته‌بندی، `type = category` و شناسه‌ها در `category_id` قرار می‌گیرند.
- در بخش برند، `type = brand` و شناسه‌ها در `brand_id` قرار می‌گیرند.
- در نوشته‌ها، اگر دسته‌بندی مشخص باشد `type = category` و در غیر این صورت `type = all` است.

## محصولات مرتبط

دکمه مشاهده همه محصولات مرتبط دیگر `type = all` ندارد. مقصد آن همیشه دسته‌بندی است و دسته‌بندی‌های مرتبط محصول در `category_id` قرار می‌گیرند:

```json
{
  "title": "مشاهده همه",
  "type": "category",
  "category_id": [350, 352],
  "brand_id": [],
  "on_sale": false,
  "url": null,
  "orderby": "date",
  "order": "desc"
}
```

## سازگاری

Action آیتم‌های بخش تصویر همچنان از قرارداد مقصد خودش استفاده می‌کند و این تغییر فقط قرارداد `view_all.action` را اصلاح می‌کند. تنظیمات قدیمی دارای `destination_id` هنگام نرمال‌سازی به ساختار جدید مهاجرت می‌شوند.
