# گزارش تغییرات Application API نسخه 2.1.0

## هدف نسخه

تنظیم API خانه از حالت ویرایش مستقیم JSON خارج شد و به یک پنل مدیریتی دیداری، بخش‌بندی‌شده و واکنش‌گرا تبدیل شد.

## روش مقداردهی به API خانه

مسیر `/wp-json/app-api/v1/home` پارامتر query دریافت نمی‌کند. مقادیر صفحه خانه در وردپرس از مسیر «ووکامرس ← Application API ← خانه» ذخیره می‌شوند و همان تنظیمات در پاسخ API اعمال می‌شوند.

- دسته‌بندی‌های ویژه: شناسه‌ها در فیلد مخصوص آن بخش، مانند `55,166,350`.
- خرید بر اساس دسته‌بندی: شناسه‌های مستقل در فیلد همان بخش.
- محبوب‌ترین برندها: شناسه‌های برند در فیلد همان بخش.
- تعداد محصولات: مقدار `per_page` داخل تنظیمات هر بخش محصول؛ مقدار پیش‌فرض ۱۰ و سقف ۳۰.

## بازگشت id و layout

هر section دوباره شامل `id` و `layout` است. `id` شناسه پایدار همان بخش و `layout` راهنمای اختیاری Flutter برای component، جهت و تعداد ستون‌ها است. `title` و `subtitle` نیز برای تمام بخش‌ها همیشه در خروجی وجود دارند.

## پنل تنظیمات

- تب خانه با تنظیمات کامل.
- تب‌های آماده برای فروشگاه، دسته‌بندی‌ها، محصول و حساب کاربری.
- فعال/غیرفعال‌کردن هر بخش.
- حذف کامل بخش غیرفعال از JSON خانه.
- نمایش فقط بخش‌های فعال در فهرست ترتیب.
- مرتب‌سازی Drag & Drop.
- دکمه‌های انتقال به بالا و پایین.
- ذخیره و نمایش مجدد ترتیب فعلی.
- کارت مستقل برای تنظیم هر بخش.
- طراحی واکنش‌گرا برای دسکتاپ، تبلت و موبایل.

## مدیریت رسانه و آیتم‌ها

برای اسلایدر اصلی، بنرهای میانی و پایانی و منوی دسترسی سریع، مدیر می‌تواند بدون نوشتن JSON:

- آیتم اضافه یا حذف کند؛
- ترتیب آیتم‌ها را تغییر دهد؛
- عنوان و زیرعنوان وارد کند؛
- تصویر یا آیکون را از Media Library انتخاب کند؛
- نوع مقصد و شناسه یا لینک مقصد را تعیین کند.

API برای تصاویر انتخاب‌شده ابتدا attachment ID را استفاده می‌کند تا لینک تصویر اصلی آپلودشده برگردد.

## سازگاری

تنظیمات JSON نسخه‌های قبلی در نبود تنظیمات جدید به‌صورت خودکار خوانده و وارد ساختار جدید می‌شوند. endpointهای محصولات و جزئیات محصول تغییری در قرارداد قبلی ندارند.
