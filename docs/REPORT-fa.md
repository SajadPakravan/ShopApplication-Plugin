# گزارش تغییرات Application API 2.3.2

## API فهرست محصولات

- برای هر محصول فهرست، فیلدهای `total_sales`، `average_rating`، `category`، `brand` و `attributes` اضافه شد تا فهرست دریافت‌شده بتواند برای جست‌وجو، مرتب‌سازی، شمارش و فیلتر محلی استفاده شود.
- `category` و `brand` هر محصول آرایه‌ای از آبجکت‌های فقط `id` و `name` هستند.
- `attributes` هر محصول فقط ویژگی‌های سراسریِ قابل فیلتر را برمی‌گرداند و هر ویژگی دارای `id`، `name` و `options` است. هر option فقط `id` و `name` دارد.
- `average_rating` در فهرست محصولات مقدار عددی است و `total_sales` عدد صحیح است.

## filters

نام کلیدها به شکل ثابت و جمع تغییر کرد:

- `categories`
- `brands`
- `attributes`

در `filters.attributes[].options` چهار فیلد وجود دارد: `id`، `name`، `color` و `image`. اگر رنگ یا تصویر برای گزینه ثبت نشده باشد رشته خالی برمی‌گردد.

## filter_by و فیلتر ویژگی

ساختار `filter_by` اکنون شامل `categories`، `brands` و `attributes` است. نمونه ویژگی انتخاب‌شده:

```json
"attributes": [
  {"id": 1, "options": [118,119]},
  {"id": 18, "options": [209,238]}
]
```

برای فیلتر ویژگی از URL می‌توان از فرم زیر استفاده کرد:

```text
?attributes[1]=118,119&attributes[18]=209,238
```

گزینه‌های یک ویژگی با رابطه «یا» و ویژگی‌های مختلف با رابطه «و» اعمال می‌شوند.

## API خانه

- تاریخ نوشته‌های بخش `posts` به تاریخ شمسی با قالب `YYYY-MM-DD` تبدیل شد و هیچ ساعت یا تاریخ میلادی در فیلد `date` نوشته نمی‌شود.
- ساختار سبک کارت محصولات صفحه خانه تغییر نکرده است؛ اطلاعات اضافه فیلتر محلی فقط در endpoint فهرست محصولات قرار دارد.

## پنل مدیریت

راهنمای تب محصولات با فیلتر ویژگی، ساختار جدید `filters` و `filter_by` و اطلاعات اضافه هر محصول به‌روزرسانی شد.
