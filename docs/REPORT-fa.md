# گزارش تغییرات Application API 2.5.1

## مشاهده همه
- تنظیمات تکراری Action از بخش «مشاهده همه» حذف شد؛ مدیر فقط فعال/غیرفعال بودن و عنوان دکمه را تنظیم می‌کند.
- عنوان خالی به‌صورت خودکار «مشاهده همه» می‌شود.
- Action از منبع همان بخش ساخته می‌شود.
- برای بخش محصولات، `type=all` و `on_sale` مستقیماً از چک‌باکس «فقط محصولات تخفیف‌دار» گرفته می‌شود.
- اگر در منبع محصولات شناسه دسته‌بندی یا برند وجود داشته باشد، اولین شناسه منبع به‌عنوان `destination_id` قرار می‌گیرد.
- برای بخش دسته‌بندی `type=category` و برای بخش برند `type=brand` است و شناسه مقصد از منبع همان بخش استخراج می‌شود.
- برای نوشته‌ها، در صورت انتخاب دسته‌بندی، مقصد همان دسته‌بندی است و در غیر این صورت مقصد `all` است.

## جزئیات محصول
- ترتیب خروجی بخش‌های پایانی ثابت است: `reviews` سپس `related_products`.
- قابلیت مرتب‌سازی و Drag & Drop این دو بخش از پنل حذف شد؛ فعال/غیرفعال‌سازی و سایر تنظیمات حفظ شده‌اند.
- پنل «فعال‌سازی بخش‌ها» بازطراحی شد تا عنوان و کنترل‌ها داخل کارت و با فاصله صحیح نمایش داده شوند.
- تنظیمات «مشاهده همه» در نظرات و محصولات مرتبط نیز فقط عنوان را از مدیر می‌گیرد و Action خودکار ساخته می‌شود.
- لیست `categories` در API جزئیات محصول اکنون والدها را از دسته اصلی تا دسته فرعی قبل از دسته‌های مستقیم محصول قرار می‌دهد و عمیق‌ترین دسته مستقیم در انتهای لیست قرار می‌گیرد.

## API صفحه دسته‌بندی
- endpoint ثابت `categories/{id}` در این نسخه وجود دارد.
- تب دسته‌بندی‌ها دارای صفحه‌ساز مستقل برای بخش‌های تصویر، محصول و دسته‌بندی است.
- بخش دسته‌بندی می‌تواند با شناسه‌های سفارشی یا حالت «نمایش دسته‌بندی‌های والد» کار کند.
- خروجی دسته‌بندی شامل `id`، `name`، `count` و تصویر اصلی است.

## بررسی فنی
- تمام فایل‌های PHP با `php -l` بررسی شده‌اند.
- فایل JavaScript با `node --check` بررسی شده است.
