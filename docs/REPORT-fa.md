# گزارش تغییرات Application API نسخه 2.0.1

## قرارداد خروجی API محصولات

در `GET /wp-json/app-api/v1/products` موارد زیر اعمال شد:

- کلید سطح اول `count` حذف شد؛ اطلاعات تعداد و صفحات فقط در `pagination` باقی ماند.
- بخش `currency` حذف شد.
- کلیدهای فیلتر به شکل مفرد تغییر کردند: `type`، `category`، `brand` و `tag`.
- `type` فقط یک رشته می‌پذیرد. در صورت ارسال‌نشدن آن، هیچ فیلتر نوعی اعمال نمی‌شود و تمام محصولات والدِ منتشرشده، از هر نوع، امکان حضور در نتیجه دارند.
- نام‌های جمع قدیمی `categories`، `brands` و `tags` موقتاً فقط به‌عنوان alias ورودی پشتیبانی می‌شوند تا نسخه نصب‌شده اپلیکیشن ناگهان خراب نشود؛ خروجی همیشه نام‌های مفرد دارد.

## فیلدهای حذف‌شده از کارت محصول

برای سبک‌تر شدن پاسخ لیست و بخش‌های محصولی صفحه خانه، این فیلدها حذف شدند:

- `slug`
- `permalink`
- `sale_price`
- `price_range`
- `variation_id`
- `variation_sku`
- `variation_attributes`
- `stock_status`
- `image_id`

فیلدهای `slug` و `permalink` و همچنین `sale_price` و `price_range` از API جزئیات محصول نیز حذف شده‌اند. شناسه و ویژگی متغیر فعلاً فقط در API جزئیات باقی مانده‌اند تا قرارداد نهایی صفحه محصول بعداً جداگانه طراحی شود.

## منطق محصول متغیر

### محصول متغیر بدون تخفیف

فهرست متغیرها بارگذاری و پیمایش نمی‌شود. قیمت حداقل همگام‌شده محصول از ردیف والد در جدول lookup ووکامرس خوانده می‌شود. در این حالت:

- `price` برابر قیمت فعلی حداقل محصول است.
- `regular_price` برابر `price` است.
- `discount_percent` برابر صفر است.
- `on_sale` برابر false است.
- تصویر و موجودی از محصول والد گرفته می‌شوند.

### محصول متغیر تخفیف‌دار

فقط زمانی که ردیف والد در lookup ووکامرس `onsale = 1` داشته باشد، متغیرهای منتشرشده بررسی می‌شوند.

هر متغیری که فروش ویژه فعال داشته باشد و قیمت فعلی آن از قیمت اصلی کمتر باشد، کاندید است. درصد واقعی تخفیف هر کاندید محاسبه می‌شود و متغیری که بیشترین درصد تخفیف را دارد انتخاب می‌شود. اگر درصد چند متغیر دقیقاً برابر باشد، اولین متغیر در ترتیب فرزندان ووکامرس حفظ می‌شود.

فیلدهای زیر کارت از متغیر منتخب ساخته می‌شوند:

- `price`
- `regular_price`
- `discount_percent`
- `image`
- `stock_quantity`
- `variation_name`

اگر متغیر تصویر اختصاصی نداشته باشد، تصویر والد استفاده می‌شود. اگر موجودی روی خود متغیر مدیریت نشود ولی روی والد مدیریت شود، موجودی والد استفاده می‌شود.

## بهینه‌سازی دیتابیس

اطلاعات lookup تمام محصولات صفحه با یک کوئری گروهی دریافت می‌شود. بنابراین برای تشخیص فروش ویژه و قیمت حداقل محصول متغیر، به ازای هر کارت یک کوئری جدا اجرا نمی‌شود. این ساختار همچنین مانع بارگذاری متغیرهای محصولات متغیرِ بدون تخفیف می‌شود.

## وضعیت تست

تمام فایل‌های PHP با `php -l` بررسی شدند و خطای syntax ندارند. تست رفتاری نهایی باید روی نسخه staging همان فروشگاه انجام شود، چون داده‌های واقعی متغیرها، افزونه برند و افزونه‌های قیمت‌گذاری فقط در محیط وردپرس فروشگاه قابل ارزیابی کامل هستند.
