# گزارش تغییرات Application API نسخه 2.7.0

## تب جدید احراز هویت

تب قدیمی «حساب کاربری» از صفحه مدیریت حذف و تب «احراز هویت» جایگزین شد. این تب تنظیمات قابل تغییر ندارد و مانند تب اطلاعات API محصولات، آدرس endpointها، پارامترها، نمونه درخواست و پاسخ، نحوه تشخیص شناسه کاربر و نکات امنیتی را توضیح می‌دهد.

## endpointهای جدید

- `POST /wp-json/app-api/v1/auth/login`
- `POST /wp-json/app-api/v1/auth/register`

هر دو endpoint فقط دو پارامتر اصلی دریافت می‌کنند:

- `identifier`: نام کاربری، ایمیل یا شماره همراه
- `password`: رمز عبور

## تشخیص خودکار شناسه

- شماره ۱۱ رقمی با پیشوند `09` به‌عنوان شماره همراه شناخته می‌شود.
- ارقام فارسی و عربی قبل از بررسی شماره همراه به ارقام انگلیسی تبدیل می‌شوند.
- مقدار دارای ساختار معتبر ایمیل به‌عنوان ایمیل شناخته می‌شود.
- سایر مقادیر معتبر به‌عنوان نام کاربری در نظر گرفته می‌شوند.

## ورود

برای ایمیل و شماره همراه ابتدا حساب وردپرس متناظر پیدا می‌شود و سپس احراز رمز عبور از مسیر استاندارد WordPress انجام می‌شود. در ورود ناموفق، پیام عمومی «شناسه کاربر یا رمز عبور نادرست است» برگردانده می‌شود تا وجود یا عدم وجود حساب قابل حدس نباشد.

## ثبت‌نام

نوع شناسه قبل از ثبت‌نام از نظر تکراری بودن بررسی می‌شود و پیام اختصاصی برای ایمیل، شماره همراه یا نام کاربری تکراری برمی‌گردد.

اگر ثبت‌نام با ایمیل یا شماره همراه انجام شود، نام کاربری به‌شکل `user-xxxxxxxx` ایجاد می‌شود. هشت کاراکتر انتهایی فقط از اعداد و حروف انگلیسی کوچک ساخته می‌شوند و قبل از ایجاد حساب یکتا بودن نام کاربری بررسی می‌شود.

- ثبت‌نام با ایمیل: ایمیل در `user_email` و `billing_email` ذخیره می‌شود.
- ثبت‌نام با شماره همراه: شماره نرمال‌شده در `app_api_mobile` و `billing_phone` ذخیره می‌شود.
- ثبت‌نام با نام کاربری: همان نام کاربری معتبر به‌عنوان `user_login` ذخیره می‌شود.
- نقش کاربر در فروشگاه WooCommerce به‌صورت `customer` ایجاد می‌شود؛ اگر این نقش وجود نداشته باشد نقش پیش‌فرض وردپرس استفاده می‌شود.

## توکن دسترسی

پس از ورود یا ثبت‌نام موفق، یک Bearer access token صادر می‌شود. توکن خام در دیتابیس ذخیره نمی‌شود و فقط هش HMAC آن در user meta نگهداری می‌شود. اعتبار پیش‌فرض توکن ۳۰ روز است و حداکثر ۱۰ توکن هم‌زمان برای هر کاربر حفظ می‌شود.

پلاگین اکنون Bearer tokenهای خودش را در فیلتر `determine_current_user` تشخیص می‌دهد تا APIهای محافظت‌شده بعدی مانند حساب کاربری، سبد خرید و علاقه‌مندی‌ها بتوانند از همین سیستم احراز هویت استفاده کنند.

## سازگاری شماره همراه

برای ورود با شماره همراه، چند کلید رایج user meta شامل `billing_phone`، `shipping_phone`، `mobile` و `phone` بررسی می‌شوند. توسعه‌دهندگان سایت می‌توانند این لیست را با فیلتر `app_api_mobile_meta_keys` گسترش دهند.
